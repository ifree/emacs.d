#+title: Emacs configuration

* Overview

This configuration targets Emacs 30 or newer and is currently tested with
Emacs 31.1 on Windows.

The configuration is split into shared modules under =config/= and small
environment selectors under =env/=.

* Environments

Set the =EMACS_ENV_NAME= environment variable before starting Emacs:

- =default=: editor, UI, and completion
- =home=: default plus programming tools and Org
- =work=: default plus programming tools

If the variable is absent, =default= is used.

* Main packages

The minibuffer stack is Vertico, Orderless, Marginalia, and Consult.
In-buffer completion is provided by Corfu.

Packages are installed through GNU ELPA, NonGNU ELPA, and MELPA on first use.

* Projects

Projects are handled by the built-in =project.el=, extended by
=lisp/project-tool.el=, and may live anywhere.  A Git repository is a
project; so is a folder outside version control that holds a
=CMakeLists.txt=, =package.json=, =pyproject.toml=, =Cargo.toml=,
=go.mod= or =*.uproject=, the outermost such folder being the root.
=C-x p a= makes any folder a project.  Added folders and favorites come
first, so one module of a large repository or of Unreal Engine can be a
project of its own.  The files of a project outside version control are
listed with =rg=, leaving out =node_modules=, =build=, the =Intermediate=,
=Binaries=, =Saved= and =DerivedDataCache= folders of Unreal Engine and
similar build output; the 196,000 files of Unreal Engine 5.8 take a
third of a second.

=C-x p p= switches project and offers a menu: =f= file, =r= ripgrep,
=b= buffer, =d= the project in the Dired sidebar, =m= Magit, =e= Eshell,
=c= compile, =o= any other command.  =C-x p D= also opens the sidebar,
switching an open one to the project; =F8= still toggles it, and =C-x d=
is plain Dired.  =F7= compiles and =F9= opens an Eshell at the bottom of
the frame, both in the project root.  Results of =C-x p g= can be edited in
place with =e= and saved with =C-c C-c=.

Important projects go into =frei/project-favorites= with a short
description, through =M-x frei/project-add-favorite= or =M-x
customize-option=.  Favorites and added folders live in =custom.el=, so
they stay on the machine and out of the repository.  Favorites are
always offered by =C-x p p=.  Emacs started without files shows the
project list, the favorites followed by the recent projects; =C-x p l=
brings it back.  Each line shows when the newest file of the project
changed, among the files =C-x p f= offers.  =rg= finds the times in the
background and they are cached in =var/project-times.eld=: a project
scanned in under two seconds is looked up whenever the list is shown,
a larger one at most once an hour, and saving a file from Emacs updates
its project at once.  In the list =RET= opens a project, =a= adds the
one at point to the favorites, =d= removes it from the favorites, the
added folders and the known projects, =g= looks up every time again and
=q= quits.

* Code analysis

=C-c a= sends the region or the buffer to the =pi= agent together with a
structural outline extracted by tree-sitter, and streams the answer into
the =*code-insight*= transcript shown to the right of the code.  When the
buffer has a grammar, the menu also offers a call graph drawn from
tree-sitter alone, without any agent (=M-x frei/code-insight-treesit-diagram=).
Entries
about any number of files accumulate there, each with its source;
=C-c a= inside the transcript sends the transcript itself, so questions
about earlier answers can be asked in place.  Names of definitions in
the answers link to the source.  Finished entries are also appended to
=var/code-insight/history.md=, which =M-x frei/code-insight-history=
brings back.  The transcript keys are =j= jump to an entry, =n= and =p=
between entries, =t= render or hide the diagrams of the entry, =s= save,
=c= copy, =o= source, =b= browser, =h= history, =k= cancel, =x= clear,
=q= quit.  The prompt is built from =templates/code-insight.md=, and the
drawing instructions for each diagram language from
=templates/diagram-*.md=; both can be edited freely.

Architecture diagrams come back as Graphviz blocks by default (see
=frei/code-insight-diagram-format= for Mermaid or PlantUML) and are
rendered inline by =documd=, the command line tool of docu.md;
=M-x frei/diagram-toggle-images= switches between the image and the
source, and =M-x frei/code-insight-open-in-browser= opens the answer in
the browser.  Without =documd= the agent is asked for plain SVG instead.
An ASCII art variant exists for documents and comments.

Run =M-x frei/treesit-install-grammars= once to install the grammars;
without them only the plain code is sent.  The same grammars turn on
the tree-sitter major modes in the =home= and =work= environments.

* External tools

Useful optional executables:

- =rg= for =consult-ripgrep=
- =pi= for code analysis
- =documd= (=npm install -g @markdown-viewer/documd=, needs Chrome) for diagrams
- =aspell= or =hunspell= for spell checking

Runtime state, backups, auto-save files, and native compilation output are
kept out of Git.
